# 🧭 JEV 사용자 시나리오 가이드 (User Scenarios Walkthrough)

JEV 플랫폼을 활용하여 실제 엔터프라이즈 환경에서 일어나는 주요 시나리오별 사용 가이드입니다.

---

## 📋 시나리오 A: 개발팀의 자원 신청 워크플로우 (Dev Team)

### 배경
서비스개발1팀의 김개발 엔지니어가 신규 결제 모듈 부하 분산 테스트를 위해 가상머신 1대가 필요합니다.

### 실행 방법 1: 웹 콘솔 자원 요청 센터 이용
1. 브라우저에서 [http://localhost:3001](http://localhost:3001)에 접속합니다.
2. 상단 헤더의 모드 스위처가 **`👨‍💻 개발팀 모드`**로 설정되어 있는지 확인합니다.
3. 좌측 메뉴에서 **[자원 요청 센터]** (`/requests`)로 이동합니다.
4. 우측 상단의 **`[+ 신규 자원 요청서 작성]`** 버튼을 클릭합니다.
5. 요청 제목, CPU 코어(4), RAM(8192MB), Disk(50GB), 신청 목적을 입력하고 `[요청서 제출하기]`를 누릅니다.
6. 티켓 번호(`REQ-XXXX`)가 발급되며 **승인 대기(PENDING)** 상태로 등록됩니다.

### 실행 방법 2: AI 인프라 챗봇 이용
1. 좌측 메뉴의 **[AI 인프라 챗봇]** (`/chat`)으로 이동합니다.
2. 채팅창에 자연어로 입력합니다:
   > *"2코어 4기가 램 20GB 디스크로 결제 모듈 테스트용 가상머신 하나 만들어줘"*
3. **AI의 동작**:
   - 직접 클러스터를 생성하지 않고, **`create_resource_request`** 도구를 스스로 선택합니다.
   - 자연어에서 `CPU 2C`, `RAM 4GB`, `Disk 20GB`를 정확히 추출하여 티켓을 발급합니다.
   - 채팅창에 `REQ-XXXX` 접수 완료 마크다운 영수증이 출력됩니다.

## 🛠️ 시나리오 B: 인프라팀의 심사 및 자동 프로비저닝 (Infra Team)

### 배경
클라우드 인프라팀의 최인프라 관리자가 개발팀에서 인입된 자원 요청을 검토하고 클러스터에 배포합니다.

### 실행 방법 1: 원클릭 자원 승인 센터 이용
1. 상단 헤더의 모드 스위처에서 **`🛠️ 인프라팀 모드`**를 클릭하여 전환합니다.
2. 좌측 메뉴의 **[자원 승인 센터]** (`/requests`)로 이동합니다.
3. 승인 대기 목록에서 김개발 엔지니어의 `REQ-XXXX` 티켓을 확인합니다.
4. 카드 우측의 **`[승인 및 프로비저닝]`** 버튼을 클릭합니다.
5. 프로비저닝 대상 노드(`pve-node-01`, 잔여 RAM 확인)와 검토 의견을 입력하고 `[승인 및 즉시 생성]`을 누릅니다.
6. **결과**:
   - `infra-service`가 Proxmox MCP의 `qemu_create`를 호출합니다.
   - 새 가상머신에 `VMID`(예: 104)와 Proxmox 태스크 `UPID`가 자동 부여되며 상태가 **`PROVISIONED`**로 변경됩니다.

### 실행 방법 2: AI 인프라 챗봇 이용
1. **[AI 인프라 챗봇]** (`/chat`)으로 이동합니다.
2. *"대기 중인 자원 요청 목록 보여줘"*를 입력하여 큐 현황을 조회합니다.
3. *"REQ-1001 승인해줘"*라고 지시합니다.
4. AI가 인프라팀 권한을 확인하고 MCP 프로비저닝을 수행한 뒤, 할당된 VMID와 결과를 채팅창에 보고합니다.

## ⚠️ 시나리오 C: 파괴적 작업 보안 승인 게이트 (Safety Gate)

### 배경
운영 중인 가상머신을 삭제하거나 강제 종료할 때 발생할 수 있는 인적/AI 실수를 방지합니다.

1. **`🛠️ 인프라팀 모드`**의 챗봇 콘솔에서 입력합니다:
   > *"105번 컨테이너 삭제해줘"*
2. **AI의 판단 (Safety Gate 동작)**:
   - `qemu_delete`는 파괴적(Destructive) 도구로 분류되어 **즉시 실행이 차단(Interrupt)**됩니다.
   - 5분 유효기간(TTL)을 가진 1회용 승인 토큰(`cf_xxxxxxxx`)이 발급됩니다.
   - 채팅창에 **"보안 승인 필요: 파괴적 작업 확인"** 경고 카드가 팝업됩니다.
3. **사용자의 승인/반려**:
   - **`[작업 승인 및 삭제 실행]`** 버튼 클릭 시, 1회용 토큰이 소비되면서 실제 삭제가 안전하게 진행됩니다.
   - 이미 소비된 토큰은 즉시 무효화되어 재실행되지 않습니다.

## 🔍 시나리오 D: AI 추론 투명성(Reasoning Trace) 감사

### 배경
AI가 왜 특정 결정을 내렸는지, 어떤 도구와 인수를 선택했는지 신뢰성을 검증합니다.

1. 챗봇 콘솔 상단의 **`[AI 툴 판단 로그 (Reasoning Trace)]`** 버튼을 클릭합니다.
2. 최근 AI가 내린 의사결정 이력 모달이 표시됩니다:
   - **발화 프롬프트**: *"딥러닝 모델 학습용 서버 신청해줘"*
   - **선택 도구**: `create_resource_request`
   - **선택 이유(Why)**: *"사용자 발화에서 고성능 AI/ML 워크로드 (8C / 16GB / 100GB) 요구사항을 판별하여 권장 사양을 도출하고 자원 요청서를 작성했습니다."*
   - **안전성 평가**: `GOVERNANCE`
   - **추론 지연시간**: `19ms`
3. 개발팀과 인프라팀 모두 AI의 판단 근거를 100% 투명하게 추적할 수 있습니다.
